# 交接载荷从不落库：模型收到的指令是空串或裸 node id

交接消息里承载「要做什么」的是 `payload`。**订阅端在写 inbox 行时就把 payload 丢了**，所以 worker 从队列里取出来的 `agent_definition` 是空串，`command_text` 退化成裸的 TaskNode id，模型收到的指令要么是 `""`，要么是 `"node-2"`。

这是 `ai4-0fwc` 的一个侧面，但两件事要分开修：0fwc 问的是「谁来调模型」，本票问的是「模型拿到什么」。即使 0fwc 把 worker 拉起来，喂给模型的仍然是一个节点 id。

## 一、实测

`worker_shell.py:38-44`：

```python
request = WorkerRequest(
    execution_id=row["dedupe_key"],
    task_node_id=row["target_id"],
    session_id=row["dedupe_key"],
    command_text=row["agent_definition"] or row["target_id"],
)
```

排一条 inbox 行（`agent_definition=''`、`target_id='node-2'`）后跑 `run_queued_once`，模型侧收到：

```
command_text = 'node-2'
```

订阅端的真实投递路径里 `agent_definition` 从不被赋值——`run_loop` 调的是 `runtime.handle_inbound(target_id, event_id)`，第三个参数取默认值 `""`（`subscriber/src/main.py`）。

## 二、payload 在哪一步消失

| 步骤 | 位置 | 手上的数据 |
| --- | --- | --- |
| 收到消息 | `subscriber/src/main.py` `run_loop` | 整个 `envelope`（含 `payload`） |
| 交给运行时 | `runtime.handle_inbound(target_id, event_id)` | **只剩两个字符串，payload 已丢** |
| 写 inbox 行 | `inbox.enqueue(..., agent_definition, ...)` | `agent_definition` 从未被传 |
| 取行执行 | `worker_shell.run_queued_once` | `agent_definition = ""` |
| 调模型 | `FastAgentDeepSeekRuntime.run(request)` | `command_text = "node-2"` |

`inbox_messages` 表里没有装 payload 的列，只有 `agent_definition TEXT NOT NULL DEFAULT ''`。也就是说**要让任务内容到达模型，需要一次 schema 变更**，不是补一个参数。

## 三、为什么不是「把 payload 塞进 agent_definition」

那样能用，但把两个概念压进一个字段：`agent_definition` 是「用哪个 agent 定义」（对应 `SCIWEAVE_AGENT_ID` / `AgentDefinition`），任务指令是「这一次要做什么」。混在一起后，`ai4-z3yq` 刚建立的「配置决定 agent，消息决定任务」的边界又糊了，而且 `AgentDefinition.instruction` 与消息里的任务文本会争同一个位置。

## 四、范围

1. `inbox_messages` 增列承载任务指令（建议 `command_text TEXT NOT NULL DEFAULT ''`），并写好向前兼容的迁移（`install.sh` 目标目录里已有旧库）；
2. `WorkAgentRuntime.handle_inbound()` 接受任务文本并落库，`subscriber` 从真实信封取（字段名取决于 `ai4-u9gj` 已确立的扁平形状，见那张票）；
3. `worker_shell` 从新列取 `command_text`，不再回退到 `target_id`；
4. 信封里确实没有任务文本时，结论要明确：是拒绝该条，还是写一条说明「只收到节点引用」的指令。**不能静默把 node id 当指令**。

**不在本票范围**：

- 谁拉起 worker → `ai4-0fwc`；
- 配置装配 → `ai4-z3yq`（已完成）；
- 信封字段读取位置 → `ai4-u9gj`（已完成）。

## Acceptance Criteria
