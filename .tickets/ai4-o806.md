# 最小 fast-agent Runtime Adapter 与固定会话恢复

将本地 Worker 的 Runtime Adapter 接入 fast-agent-mcp，使用不需要真实模型凭据的 passthrough 模型完成一次 Agent loop；Gateway 为 TaskNode 管理稳定 session_id 和专属持久 home，新的 Worker 可以恢复同一 fast-agent 会话。

## Acceptance Criteria

- [ ] 记录并锁定 fast-agent-mcp 的实现版本、来源、用途和安装/验证命令，不臆造未声明依赖。
- [ ] Runtime Adapter 使用 Gateway 管理的稳定 session_id、专属持久 home、connection scope 和 session history。
- [ ] 首次 Worker 能使用 passthrough 模型完成一次 Agent loop，并把结果和运行时版本写入 ExecutionRecord。
- [ ] Worker 结束后释放进程，fast-agent 会话文件保留在受配置控制的持久目录。
- [ ] 新 Worker 使用同一 task_node_id/session_id/home 可以恢复历史并完成后续一次 loop。
- [ ] 默认关闭自动 compaction，跨 TaskNode 不共享 session_id 或会话目录。
- [ ] fast-agent 失败、会话无法恢复和持久目录不可用时，Gateway 保存可查询的失败状态和审计事件。

> 范围说明（2026-10-19）：本票只覆盖 Worker 侧运行时接入，与 Owner 入口协议无关。Owner 通道已由 A2A 改为 MCP（Streamable HTTP），不影响 Runtime Adapter 的 run/resume/cancel 接口和固定会话恢复要求。见 [Owner 通道与上游交接队列物理隔离](ai4-353s.md)。
