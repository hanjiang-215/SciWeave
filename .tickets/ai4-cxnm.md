# 自建 literature-search MCP：arXiv 与 Crossref 双源检索

预设文献 Agent 要能联网检索，但套件目前没有任何联网能力：`libs/mcp-libs/` 五张卡全是中央领域服务（草稿箱、地图、wiki、邮件、SciencePal），`libs/local-mcp-libs/local-literature.yaml` 只有一个 `search` 工具的占位卡，背后没有服务实现。

## 为什么不自建不行：现成 MCP 装不进来

`runtime/src/work_agent_runtime/mcp_resources.py:37` 对 stdio 传输做了硬性白名单：

```python
if transport == "stdio" and startup and (
    startup.get("executable") != "uv"
    or startup.get("args") != ["run", "--env-file", ".env", "python", "src/main.py"]
    or not startup.get("project_dir_env")
):
    raise MCPResourceError("unsafe_startup", name)
```

实测把一个 `uvx arxiv-mcp-server` 形态的卡片喂给 `load_mcp_registry`，直接被拒：

```
[unsafe_startup] arxiv-literature
```

所以 `arxiv-mcp-server`（PyPI 0.8.2，Apache-2.0）、`duckduckgo-mcp-server`（PyPI 0.7.0，**未声明许可证**）这类现成第三方 MCP 一张都进不来。要么放宽这条安全边界，要么自己写。本票选自写。

## 数据源实测（2026-10-27，本机 curl 直连）

| 源 | 端点 | 需要 key | 实测 |
| --- | --- | --- | --- |
| arXiv Atom API | `https://export.arxiv.org/api/query?search_query=...` | 否 | HTTP 200，29KB，需 `-L` 跟随 301 |
| Crossref REST | `https://api.crossref.org/works?query=...&rows=1` | 否 | HTTP 200，返回 `title` / `DOI` / `license[].URL` |
| OpenAlex | `https://api.openalex.org/works?search=...` | 否（免费 key 可选） | HTTP 200，但免费额度是**共享 IP 每天 $0.10** |

DDG 在本机不通（`lite.duckduckgo.com` 与 `en.wikipedia.org` 都 `HTTP 000` 超时），不作为候选。OpenAlex 的共享 IP 限额意味着它不能当默认源，本期不接。

## Design

新增 `sci-weave/toolkits/researcher-agent-toolkit/deploy-task-agent/custom-mcp/literature-search/`，独立 Python 子项目（自己的 `pyproject.toml` 与 `uv.lock`，按 AGENTS.md 独立子项目规则），`src/main.py` 是唯一启动入口，stdio 传输。

依赖：`mcp>=2.3,<3`（与 `custom-mcp/sciencepal-bridge` 一致）、`httpx>=0.28,<1`。不引入 XML 解析新依赖，arXiv Atom 用标准库 `xml.etree.ElementTree`。

工具面**只开两个**：

| 工具 | 入参 | 出参 |
| --- | --- | --- |
| `search` | `query`（必填）、`source`（`arxiv`\|`crossref`，缺省 `arxiv`）、`limit`（缺省 5，上限 20） | 结果数组，每条含 `title` / `authors` / `published` / `id`（arXiv id 或 DOI）/ `abstract` / `url` / `source` |
| `get_abstract` | `id`（必填，arXiv id 或 DOI）、`source`（可选，缺省按 id 形态判断） | `title` / `abstract` / `authors` / `published` / `url` / `license` |

不开 `download_paper` / `check_alerts` / `citation_graph`：这些是 `arxiv-mcp-server` 的增值功能，不是「文献 Agent 能跑起来」的必要条件。`semantic_search` 需要它的 pro 版，更不做。

卡片放 `libs/mcp-libs/literature-search/mcp.json`，`transport: stdio`，`startup` 严格写成白名单形态：

```yaml
transport: stdio
startup:
  executable: uv
  args: [run, --env-file, .env, python, src/main.py]
  project_dir_env: LITERATURE_MCP_PROJECT_DIR
```

## Acceptance Criteria

- [ ] `custom-mcp/literature-search/` 是独立可运行的 `uv` 子项目，`src/main.py` 是唯一入口，`uv run --env-file .env python src/main.py` 能起 stdio MCP 服务。
- [ ] `search` 支持 `arxiv` 与 `crossref` 两个 `source`，各返回至少 `title` / `id` / `authors` / `published` / `url`；`limit` 上限 20，超限返回稳定错误而不是静默截断。
- [ ] `get_abstract` 能按 arXiv id 与 DOI 两种形态取回摘要，两种都返回 `license` 字段（arXiv 走 Atom 的 `license` 链接，Crossref 走 `license[].URL`，缺失时返回 `null` 而不是编造）。
- [ ] 网络失败、上游 5xx、超时、返回体结构变化都映射为稳定错误码，不抛裸异常；单次调用不重试超过 2 次，总耗时上限 30 秒。
- [ ] `libs/mcp-libs/literature-search/mcp.json` 的 `startup` 与 `runtime/src/work_agent_runtime/mcp_resources.py:37` 的白名单逐字匹配，`load_mcp_registry` 加载成功（补一条测试固化这个契约）。
- [ ] 新增依赖 `mcp`、`httpx` 在子项目 `pyproject.toml` 与 `uv.lock` 中声明，并在 `docs/DEPENDENCIES.md` 记录来源、用途、许可证与安装验证命令。
- [ ] 测试覆盖：两个源的成功解析（用固定响应体，不打真实网络）、上游错误的稳定映射、`limit` 越界、`id` 形态识别；测试不依赖真实网络与真实凭据。
- [ ] 不在源码、测试、文档中硬编码部署路径或端口；上游端点通过环境变量可覆盖（缺省用公开端点）。

## Not in Scope

- 不放宽 `mcp_resources.py` 的 `unsafe_startup` 白名单。第三方 `uvx` MCP 仍然装不进来，这是本票的前提而不是待办。
- 不接 OpenAlex（免费额度是共享 IP 每日 $0.10，不能当默认源），也不接 DDG。
- 不做论文全文下载、PDF 解析、BibTeX 导出、引用图、订阅提醒。
- 不改 `libs/local-mcp-libs/local-literature.yaml` 那个占位卡；它的去留由 `ai4-tj83`（出厂卡片权限切分）一并决定。
- 不做 Google Scholar / Semantic Scholar（后者需要 key）。
