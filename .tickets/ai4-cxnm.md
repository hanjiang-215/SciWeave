# 自建 literature-search MCP：arXiv 与 Crossref 双源检索

预设文献 Agent 要能联网检索，但套件目前没有任何联网能力：`libs/mcp-libs/` 五张卡全是中央领域服务（草稿箱、地图、wiki、邮件、SciencePal），`libs/local-mcp-libs/local-literature.yaml` 只有一个 `search` 工具的占位卡，背后没有服务实现。

## 为什么不自建不行：现成 MCP 装不进来

`runtime/src/work_agent_runtime/mcp_resources.py:37` 对 stdio 传输做了硬性白名单：

```python
if transport == "stdio" and startup and (
    startup.get("executable") != "uv"
    or startup.get("args") != ["run", "--env-file", ".env", "python", "src/main.py"]
    or not startup.get("project_dir_env")
):
    raise MCPResourceError("unsafe_startup", name)
```

实测把一个 `uvx arxiv-mcp-server` 形态的卡片喂给 `load_mcp_registry`，直接被拒：

```
[unsafe_startup] arxiv-literature
```

所以 `arxiv-mcp-server`（PyPI 0.8.2，Apache-2.0）、`duckduckgo-mcp-server`（PyPI 0.7.0，**未声明许可证**）这类现成第三方 MCP 一张都进不来。要么放宽这条安全边界，要么自己写。本票选自写。

## 数据源实测（2026-10-27，本机 curl 直连）

| 源 | 端点 | 需要 key | 实测 |
| --- | --- | --- | --- |
| arXiv Atom API | `https://export.arxiv.org/api/query?search_query=...` | 否 | HTTP 200，29KB，需 `-L` 跟随 301 |
| Crossref REST | `https://api.crossref.org/works?query=...&rows=1` | 否 | HTTP 200，返回 `title` / `DOI` / `license[].URL` |
| OpenAlex | `https://api.openalex.org/works?search=...` | 否（免费 key 可选） | HTTP 200，但免费额度是**共享 IP 每天 $0.10** |

DDG 在本机不通（`lite.duckduckgo.com` 与 `en.wikipedia.org` 都 `HTTP 000` 超时），不作为候选。OpenAlex 的共享 IP 限额意味着它不能当默认源，本期不接。

## Design

新增 `sci-weave/toolkits/researcher-agent-toolkit/deploy-task-agent/custom-mcp/literature-search/`，独立 Python 子项目（自己的 `pyproject.toml` 与 `uv.lock`，按 AGENTS.md 独立子项目规则），`src/main.py` 是唯一启动入口，stdio 传输。

依赖：`mcp>=2.3,<3`（与 `custom-mcp/sciencepal-bridge` 一致）、`httpx>=0.28,<1`。不引入 XML 解析新依赖，arXiv Atom 用标准库 `xml.etree.ElementTree`。

工具面**只开两个**：

| 工具 | 入参 | 出参 |
| --- | --- | --- |
| `search` | `query`（必填）、`source`（`arxiv`\|`crossref`，缺省 `arxiv`）、`limit`（缺省 5，上限 20） | 结果数组，每条含 `title` / `authors` / `published` / `id`（arXiv id 或 DOI）/ `abstract` / `url` / `source` |
| `get_abstract` | `id`（必填，arXiv id 或 DOI）、`source`（可选，缺省按 id 形态判断） | `title` / `abstract` / `authors` / `published` / `url` / `license` |

不开 `download_paper` / `check_alerts` / `citation_graph`：这些是 `arxiv-mcp-server` 的增值功能，不是「文献 Agent 能跑起来」的必要条件。`semantic_search` 需要它的 pro 版，更不做。

卡片放 `libs/mcp-libs/literature-search/mcp.json`，`transport: stdio`，`startup` 严格写成白名单形态：

```yaml
transport: stdio
startup:
  executable: uv
  args: [run, --env-file, .env, python, src/main.py]
  project_dir_env: LITERATURE_MCP_PROJECT_DIR
```

## Acceptance Criteria

- [x] `custom-mcp/literature-search/` 是独立可运行的 `uv` 子项目，`src/main.py` 是唯一入口，`uv run --env-file .env python src/main.py` 能起 stdio MCP 服务。
- [x] `search` 支持 `arxiv` 与 `crossref` 两个 `source`，各返回至少 `title` / `id` / `authors` / `published` / `url`；`limit` 上限 20，超限返回稳定错误而不是静默截断。
- [x] `get_abstract` 能按 arXiv id 与 DOI 两种形态取回摘要，两种都返回 `license` 字段（~~arXiv 走 Atom 的 `license` 链接~~ → arXiv 恒为 `null`，见下方验收修正；Crossref 走 `license[].URL`，缺失时返回 `null` 而不是编造）。
- [x] 网络失败、上游 5xx、超时、返回体结构变化都映射为稳定错误码，不抛裸异常；单次调用不重试超过 2 次，总耗时上限 30 秒。
- [x] `libs/mcp-libs/literature-search/mcp.json` 的 `startup` 与 `runtime/src/work_agent_runtime/mcp_resources.py:37` 的白名单逐字匹配，`load_mcp_registry` 加载成功（补一条测试固化这个契约）。
- [x] 新增依赖 `mcp`、`httpx` 在子项目 `pyproject.toml` 与 `uv.lock` 中声明，并记录来源、用途、许可证与安装验证命令（**不记在 `docs/DEPENDENCIES.md`**：该文件第 14 行明确把 Python 服务与 MCP 的业务依赖排除在范围外，见下方验收修正；实际记在 `custom-mcp/literature-search/README.md` 的「依赖」一节）。
- [x] 测试覆盖：两个源的成功解析（用固定响应体，不打真实网络）、上游错误的稳定映射、`limit` 越界、`id` 形态识别；测试不依赖真实网络与真实凭据。
- [x] 不在源码、测试、文档中硬编码部署路径或端口；上游端点通过环境变量可覆盖（缺省用公开端点）。

## Not in Scope

- 不放宽 `mcp_resources.py` 的 `unsafe_startup` 白名单。第三方 `uvx` MCP 仍然装不进来，这是本票的前提而不是待办。
- 不接 OpenAlex（免费额度是共享 IP 每日 $0.10，不能当默认源），也不接 DDG。
- 不做论文全文下载、PDF 解析、BibTeX 导出、引用图、订阅提醒。
- 不改 `libs/local-mcp-libs/local-literature.yaml` 那个占位卡；它的去留由 `ai4-tj83`（出厂卡片权限切分）一并决定。
- 不做 Google Scholar / Semantic Scholar（后者需要 key）。

**验收修正 1：arXiv 的 `license` 恒为 `null`。** 原验收写「arXiv 走 Atom 的 `license` 链接」，实现时实测这个前提不成立：公开 Atom API 根本不返回许可证元素。查了 50 条分类查询（`all:electron` 50 条、`cat:cs.CL` 30 条、`cat:math.HO` 30 条）、老式 id（`hep-th/9901001`）与 3 条已知论文的 `id_list` 查询，`license` 字样出现 **0 次**；feed 的命名空间里也只有 `opensearch` 与 `arxiv`，没有许可证扩展。所以 arXiv 结果的 `license` 一律返回 `null`，并在代码注释、卡片的 `description` 和 README 里都写明「`null` 表示源没声明，不是公有领域」——从 abs 页面抓许可证是编造，不做。Crossref 侧正常：`license[].URL` 有时返回（实测 `10.1038/nature14539` 得到 `https://www.springer.com/tdm`），有时是 `null`（`10.1049/ic:19981011`），两种都有测试覆盖。

**验收修正 2：依赖记录不写进 `docs/DEPENDENCIES.md`。** 原验收要求在那份文件记录 `mcp`/`httpx` 的来源、用途、许可证与安装验证命令，但该文件第 14 行写的是「Python 服务、MCP、Vue 前端及其业务依赖不在本文定义；它们必须由对应子项目的 `pyproject.toml`、`uv.lock`、`package.json` 和锁文件声明」。`ai4-g1km` 在 2026-10-26 已经因为同样原因修正过它的第 1 条验收，这里沿用同一口径：依赖声明在 `pyproject.toml` + `uv.lock`，来源/用途/许可证/验证命令记在 `custom-mcp/literature-search/README.md` 的「依赖」一节（`mcp` 2.3.0 MIT、`httpx` 0.28.1 BSD-3-Clause）。

实现要点：

- 错误一律走 `{"error": {"code", "message"}}` 信封，8 个码与卡片 `failures` 一致；未预期异常转成 `literature_internal` 而不是让 stdio 会话断在半路。
- 重试只覆盖 408/425/429/5xx 与超时，最多 2 次，总预算 30 秒；其余 4xx 立即失败（测试断言 403 只发一次请求）。
- Crossref 的 JATS 摘要先剥标签再反转义，反转义后残留的少量格式化标签按白名单清掉——不用一刀切 `<[^>]+>`，否则 `x < y and z > w` 这种数学记号会被吃掉。
- 上游端点、超时、联系邮箱全部走环境变量；`User-Agent` 带上 `mailto:`（配了才有）。
- 前端 `limit` 越界在发请求前就拒绝，测试断言此时 `recorder.requests == []`。
