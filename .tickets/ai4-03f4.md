# GitHub Actions 首次执行：6 个测试模块在 ubuntu/windows 上失败

GitHub Actions 第一次真正执行 `scripts/ci.sh` 时，两个 runner 上共有 6 个测试模块失败。这些失败不是上传动作引入的：Gitee 不执行 `.github/workflows/ci.yml`，所以 develop 上的这些用例从未在 CI 里跑过。

## 失败清单与根因

| 模块 | 平台 | 根因 |
|---|---|---|
| `centre-agents/worker` | 两平台 | 测试 fixture 只给了 MCP `*_URL`，而随仓库发布的卡片同时声明 `*_TOKEN`（ai4-sue2 后装配器强制要求）；另外 `validate_runtime` 对同一个越界 session 目录在 Windows/POSIX 给出两条不同报错 |
| `gateway/subscriber` | 两平台 | B1 把 `task_completed` 的发布时机从「worker 跑完」挪到「研究员 confirm_execution」，三个测试仍断言旧契约 |
| `research-map` | 两平台 | `ExecutionStatusResolver` 的测试表缺 `result_summary`/`confirmation_status` 两列，整个读取静默降级；B1 新增的可执行前沿推导没有测试覆盖；`create_candidate_snapshot` 新增的 schema 声明写入没有更新请求序列断言 |
| `deploy-task-agent/runtime` | Windows | systemd unit 转义在 Windows 路径上要把反斜杠加倍；binding JSON 断言比原始文本而非解析字段；`bootstrap_wiki` 未在权限清单里分类；systemd hook 的用例在非 POSIX 上无法成立 |
| `toolkits/suitecheck` | Windows | `hook_not_executable` 检查 POSIX 可执行位，NTFS 上没有这个属性，Windows 上写出的套件永远被判错 |

## 验收标准

- GitHub Actions 的 `ubuntu-latest` 与 `windows-latest` 两个 job 全部通过
- 本地 `scripts/ci.sh` 通过（含前端 vitest + build、compileall、`git diff --check`）
- 不改变任何业务行为：只修测试与平台判定，唯一的 src 改动是给 `get_execution` 补一列已有字段

## Acceptance Criteria

- [ ] GitHub Actions `ubuntu-latest` job 通过
- [ ] GitHub Actions `windows-latest` job 通过
- [ ] 本地 `scripts/ci.sh` 全绿
- [ ] 无业务行为变更（仅测试与平台判定；`get_execution` 增加 confirmation_status 列）
