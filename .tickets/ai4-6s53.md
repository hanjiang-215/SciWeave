# Mapping 候选提交与校验纵向实现

实现 Research Mapping 变更从正式基线进入可审阅候选的纵向路径：接收一个符合领域模型的 TaskNode/DependencyEdge 变更单元，执行结构和关系校验，在隔离候选中保存不可变快照，并记录对应治理对象与审计证据。

## Design

遵循已关闭的 TaskNode/DependencyEdge 字段模型、Proposal 生命周期与 SQLite 持久化规格；正式基线读取复用本地图的 Mapping 正式版本查询任务。候选提交不改变当前正式指针，重复提交按已有幂等语义处理。Python + uv；SQLite 保存治理状态，TerminusDB 保存图快照，不假设未确认的 SDK/API。

## Implementation Contract

- **代码位置与边界：** 在 `sci-weave/research-mapping/src/research_mapping/candidate_submission.py` 实现 `MappingCandidateService.submit(change_set, idempotency_key)`；扩展本项目既有 SQLite schema/Store 和 `TerminusStore`，不重建子项目骨架、不新增第三方依赖。
- **输入与输出：** 输入必须绑定 mapping domain、提交者、精确 `base_formal_revision_id`（首版领域规格允许的初始状态除外）、稳定提交身份、TaskNode/DependencyEdge 变更单元和幂等键。成功结果返回原 Submission/Proposal/CandidateCommit 稳定 ID、候选 branch 与精确 commit hash；拒绝或结果未知不返回可审阅候选。
- **校验与存储：** 按已关闭的 TaskNode/DependencyEdge 规格校验端点/版本/状态、禁止自环和 blocking 子图环；验证基准仍匹配当前正式版本。扩展 `TerminusStore.create_candidate_snapshot(domain_id, base_commit_ref, canonical_snapshot, idempotency_key)`，返回确认/明确失败/结果未知及精确 commit ref；候选正文仅由 TerminusDB 保存。SQLite 以单一本地事务写入 Submission、Proposal、CandidateCommit 及关联 AuditEvent。
- **幂等和失败：** 规范化 change set 后使用 SHA-256；重复的相同操作返回原结果。幂等身份与提交者、领域、提交 ID、精确基准和内容摘要绑定；相同身份对应不同内容返回 `idempotency_conflict`。确定性校验失败返回稳定错误码；TerminusDB 明确失败返回存储错误；提交/读回或 SQLite 持久化结果未知时返回操作结果 `result_unknown`，保留已有存储证据并按原身份读回对账，重试不得创建第二个逻辑 Submission 或覆盖既有候选。
- **测试与配置：** 新增 `tests/test_candidate_submission.py`，用临时 SQLite 和 Fake TerminusStore 验证成功、关系/环校验、过期基准、幂等重试/冲突、TerminusDB 明确失败和结果未知；按 Mapping 地图的 `.env` 变量和 README 命令验证，不依赖固定端口。

## Acceptance Criteria

- [ ] 合法变更单元以不可变快照进入隔离候选，并生成可追踪的 Submission、Proposal、CandidateCommit 和审计关联。
- [ ] 缺失关系目标、版本/状态违规、自环、blocking 子图成环或过期正式基准被拒绝；正式版本和既有候选不受影响。
- [ ] 相同幂等身份及内容返回第一次持久化结果；同一提交身份绑定不同基准/内容/提交者时显式冲突，不覆盖原候选。
- [ ] 候选快照精确记录 TerminusDB store/branch/commit hash 和规范内容摘要；SQLite 仅持有治理事实和精确定位。
- [ ] TerminusDB 确认、拒绝与未知结果均可区分；结果未知时不谎报成功、不盲目重写，且可按同一身份对账。
- [ ] `test_candidate_submission.py` 覆盖上述成功与拒绝/失败/未知分支；标准库测试和已锁定环境验证命令记录在交付证据中。
