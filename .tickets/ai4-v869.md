# SciencePal 承载执行面与中央服务 MCP 对接：方案、风险与解决预案

本票登记 SciencePal 与 SciWeave 中央服务的对接方案和风险预案；**实现延后**：待团队把项目闭环后（即 `ai4-aaff` 的两条 SciencePal 验收项进入实演阶段）再按本票执行。当前不写实现代码、不改中央服务。

## Design

### 一、对接方案：执行面与治理面分离

| 层 | 承载对象 | 落地形态 |
| --- | --- | --- |
| SciencePal（执行面） | T1 数据检查、T2 分析执行、失败注入/重试、sub-agent 团队 | 沙箱内跑脚本；T1/T2 脚本以显式 skill 装载；agent 定义 + 固定任务指令模板 |
| 中央服务器（治理面） | Formal Mapping、Proposal/Diff/正式化、Execution Record、审计账本 | 现有 `research-map` / `research-wiki` 管理 MCP + TerminusDB + SQLite，对外发布 Streamable HTTP + Bearer 端点 |
| MCP（契约面） | agent 以 MCP client 身份调用中央治理能力 | Streamable HTTP + JSON-RPC；Bearer 鉴权；能力档最小授权 |

**概念澄清（评审时可能被问倒的点）**：MCP server 部署在中央服务器，不是"装进 SciencePal"；装进 SciencePal 的是 skill、agent 定义和 MCP client。SciencePal 沙箱执行分析计算，中央服务器执行治理裁决。

### 二、两条实现路径（覆盖 SciencePal 扩展机制的不确定性）

- **路径 A（原生 MCP）**：若 SciencePal 支持配置外部 MCP server，直接挂中央端点，agent 原生看到 `get_formal_mapping` / `submit_candidate` / `preview_candidate` 等工具。这是 `run_iris_mapping_pipeline.py` 已实跑过的调用形态。
- **路径 B（skill 桥，保底）**：若 SciencePal 不支持原生 MCP，把 MCP JSON-RPC client 封装成一个 skill（内部即 HTTP 调用中央管理端点）。行为与路径 A 等价，差别只在 agent 用"原生工具"还是"skill 调起"。MCP over Streamable HTTP 本质是 HTTP + JSON-RPC，路径 B 无技术障碍。

### 三、权限与人工接管点

- SciencePal agent 凭据只开放 `read` + `candidate_submit` 能力档；`candidate_review` / `formalize` 不放给 agent。
- 人工接管点固定为三处：T3 结果由 TaskNode Owner 人工接纳；Mapping Proposal 由 Project Owner 人工批准/驳回；agent 自修仍失败的执行转人工接管。
- 每次 MCP 调用照常写中央接口层审计账本，SciencePal 侧不再造审计副本。

### 四、与既有规范的对应

- 套件边界（`ai4-v19u`，closed）：本方案即「领域 MCP 是 Agent 能力来源 + Skills 只认显式清单 + 最小权限 Agent profile」的具体化；SciencePal 相当于托管形态的端侧 Agent 宿主。
- 领域 MCP（`ai4-w73z` 实现的切片）：工具面、五档鉴权、接口层审计已实跑验证，中央侧零改造即可作为 MCP server 发布。

## 可能遇到的问题与解决预案

1. **SciencePal 扩展机制不公开**（平台闭源，GitHub 同名仓库为无关占位仓库，官网内容需登录）。
   - 影响：无法提前确认原生 MCP 配置、沙箱出站、skill 装载格式。
   - 预案：注册后立即上传最小测试 skill 测三项（脚本执行、沙箱出站到中央端点、原生 MCP 配置），据此定路径 A 或 B；路径 B 为保底。

2. **中央服务公网可达性**。
   - 影响：评审期 SciencePal 沙箱必须能访问中央端点；内网/本机地址不可达则现场演示失败；赛事要求项目链接可访问否则限时补正。
   - 预案：管理 MCP 发布公网 HTTPS + Bearer token（全走 env 配置，无硬编码）；评审期用隧道（cloudflared/ngrok）或轻量云保持在线；Replay 链接 + 输出 JSON 作为证据兜底；演示前跑可达性检查。

3. **中央服务稳定与数据一致**。
   - 影响：TerminusDB + SQLite 需随服务器端运行；审计写工具 fail-closed 会影响 agent 调用链。
   - 预案：容器化部署（复用现有 compose）；`health` 工具检查；调用失败由 agent 重试；评审前全链路演练。

4. **公网暴露的安全边界**。
   - 影响：管理 MCP 暴露公网后可能被越权调用或探测。
   - 预案：Bearer 鉴权（已实现）；agent 仅 `read` + `candidate_submit`；令牌只存服务器 env，不入仓库；不把 `formalize` / `review` 给 agent。

5. **SciencePal 沙箱环境与本地不一致**。
   - 影响：Python 版本、标准库行为或网络限制差异可能导致 T2 结果漂移。
   - 预案：T1/T2 仅用 Python 标准库、参数固定（K=3、种子 `20261023`）；回填时记录沙箱真实环境版本；若结果与本机不一致，以沙箱实际输出为准并同步证据卡。

6. **评审可用性与可复现**。
   - 影响：评审时段 SciencePal 项目链接失效、沙箱生命周期重置、中央服务掉线。
   - 预案：Replay 链接 + 录屏 + 输出 JSON 三重证据；演示脚本固定；提交前逐项检查清单。

7. **赛事规则边界**。
   - 影响：SciencePal 只承担文案不达标；或核心步骤全部在本机执行导致"未实质使用 SciencePal"。
   - 预案：T1/T2 必须在 SciencePal 沙箱真实执行并留 Replay 链接；本机结果只作复现对照，不冒充 SciencePal 实演。

8. **时间风险**。
   - 影响：作品提交 10/31 截止；SciencePal 注册/沙箱首启/出站配置不可控。
   - 预案：注册后当天跑最小验证；预留至少 2 天缓冲；若 SciencePal 侧不可行，以本机真实治理链路 + Replay/录屏作为最后兜底并在项目说明中如实标注（不满足赛事硬门槛，属最后手段）。

## 延后执行的边界

本票只登记方案与风险预案，不进入实现。执行触发条件：团队把项目闭环后（`ai4-aaff` 的本地侧证据已齐备，SciencePal 实演阶段启动时）。执行时按本票预案先做最小能力验证，再走路径 A/B 与权限设计；每步产出回写本票 Notes。
