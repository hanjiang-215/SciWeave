# Task Owner A2A Gateway 与上游交接队列物理隔离

## Question
确定端侧 Task Agent 的两类触发在物理层面的隔离方式：Task Owner 的补充、返修、重试、暂停和取消是否通过 A2A 调用常驻 Task Agent Gateway；上游 TaskNode 的一次性交接是否继续通过消息队列和上游收集器处理。需要明确 Gateway、上游收集器与短生命周期 Worker 的职责，A2A 请求的持久化、授权、审计、幂等性、取消语义，以及 Gateway 是否可在内部投递作业而不改变 Owner 通信语义。该票不选择具体消息队列、A2A 服务框架或部署方案。

## Acceptance Criteria

形成可供后续流程设计使用的物理隔离规格：明确 Owner A2A 调用、上游队列交接、常驻 Gateway、常驻上游收集器和短生命周期 Worker 的边界；明确 Owner Command 的持久化与审计，以及 Worker 释放后继续接收 Owner 指令的方式。


## Notes

**2026-10-19T03:03:47Z**

设计与验证更新（2026-10-19）：确认 A2A 不要求执行 Worker 常驻。物理隔离采用：Task Owner 的 Codex -> A2A -> 常驻 Task Agent Gateway -> 按需创建/控制短生命周期 Worker；上游 TaskNode 审核通过 -> 上游交接消息队列 -> 常驻上游收集器 -> 收齐并满足 Dependency Edge 后创建 Worker。Gateway 和上游收集器常驻，Worker 在一个 loop 后释放；Buffer、Owner Command、Execution Record 和 AuditEvent 留在平台侧。A2A 原型验证已在 drafts/fast-agent-startup-test/ 通过，验证的是本地 A2A server 与 fast-agent A2A client 的最小启动与响应，未验证 Gateway 的授权、命令持久化、幂等、取消或内部作业投递。
