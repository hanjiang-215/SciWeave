# 多人和多 Agent 协作执行

## Question
人类、Agent、负责人和审核者如何围绕研究图共同执行？需要在宏观层面决定：任务由谁负责、工作如何交接、前置结果如何推动后续任务、哪些工作必须由人完成、哪些工作允许 Agent 自主推进。暂不讨论具体消息队列实现。

## Acceptance Criteria

明确协作参与者、任务交接、责任边界和人类介入的一级功能；形成后续执行模型的产品约束。

## Answer

平台以研究图中的任务节点作为协作单位，但节点负责人可以是一个协作集合，而不限定为单个人或单个 Agent。例如头脑风暴节点可以由全部研究人员与部分节点 Agent 共同参与；后续节点再根据任务性质指定单人、多人、Personal Agent 或轻量任务 Agent。

Agent 主要处理重复、耗时、结构化的科研工作，包括文献搜集整理、数据处理、仿真实验设计与验证、论文和报告写作等。研究人员主要负责真实实验、科研判断、头脑风暴、推进未知节点、维护研究路线图、查看公共资源和了解项目进度，并负责所有审计。

研究人员通过自己的 Personal Agent 接入平台。平台不要求所有研究人员直接维护资源或具备计算机背景，而是通过标准化的 Skills、MCP、系统提示词和 Hooks，让其 Personal Agent 代为访问、整理和维护可授权的公共资源。平台侧独立研究 Agent 使用轻量化、可配置的任务 harness。

中央 Agent 负责调度系统、任务状态、研究图维护、Proposal/PR 初步处理以及人员和 Agent 注册信息维护，但不替代负责人进行科研审计。任何 Agent 结果都不能直接进入公共资源，必须经过负责人审核后放行。

普通执行失败可以重试、转交或由人接管；如果失败意味着研究假设、任务前置条件或路线发生变化，则应生成路线调整 Proposal，由负责人审核后更新动态研究图。
