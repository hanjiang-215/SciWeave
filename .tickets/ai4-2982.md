# Research Mapping 正式快照查询接口与交接协调服务访问边界

明确交接协调服务如何读取 Research Mapping 当前正式快照。Research Mapping 可能通过管理 MCP 或其他 HTTP 接口提供服务，需要裁决传输方式、只读查询契约、版本一致性、鉴权和禁止直连存储边界。

## Design

需要决定：1. 交接协调服务使用 MCP Streamable HTTP、内部 HTTP 查询接口或其他稳定适配器；2. formal_revision_published 后如何按 formal_revision_id 获取一致快照；3. 查询返回 TaskNode、DependencyEdge、版本、输出、激活条件和 executor_refs 的最小集合；4. 领域服务不可用、版本不存在、快照过期时的错误；5. 交接协调服务不得直连 Research Mapping SQLite 或 TerminusDB；6. 调用鉴权、审计和接口版本兼容边界。

## 已定契约（2026-10-25 收口）

### 传输方式与部署边界

交接协调服务通过 **research-map 管理 MCP（Streamable HTTP，`POST /mcp`）** 读取正式快照，与 Centre Agent 等其他跨模块调用方共用同一对对外端点；不另设内部 HTTP 查询接口、不按调用方复制领域服务。接口只在服务启动加载领域服务后可用（`GET /health` 就绪），地址/端口/令牌经 `SCIWEAVE_MAPPING_MCP_*` 环境变量配置。调用方与交接协调服务同属 central 部署单元，但接口身份仍走 MCP 令牌映射，不以"同进程"豁免鉴权。

### 请求/响应契约

新增只读工具 `get_formal_mapping_at_revision`（`mapping_domain_id` + `formal_revision_id`）：

- 成功返回 `status: available` 与 `formal_revision_id`、`store_id`、`branch_id`、`commit_hash`、`content_digest`、`documents`（TaskNode / DependencyEdge 文档数组，含 `logical_id`/`version_id`/`task_owner_id`/`executor_refs`/孩子编号等字段），足以重建版本一致的最小依赖图。
- 目标版本未被正式激活或不存在时返回 `no_such_revision`；存量数据不一致（如指针指向缺失版本、成功结果与版本不匹配、快照身份/摘要/计数不一致）由既有 `inconsistent` 语义覆盖，调用方不得把该结果当作空图继续派发。

### 快照一致性、错误与重试语义

读取链路与 `get_formal_mapping` 共用**同一套一致性闸门**（形式化成功结果匹配、精确 commit 快照身份匹配、图摘要与节点/边计数匹配），按 `formal_revision_id` 读取时同样强制，不因"按版本名"而放松：

- 版本存在但从未成功形式化 → `inconsistent`（不得产生内容）。
- TerminusDB 连接失败或快照缺失 → `unavailable`（reason_code 细分），对应「领域服务不可用」。
- 版本不存在的稳定码为 `no_such_revision` / `revision_not_found`；调用方重试前应先确认版本号来自正式版本事件或历史指针，而不是盲轮询。

重试语义：交接协调服务对 `unavailable` 做退避重试；对 `inconsistent` 与 `no_such_revision` 视为不可恢复，记录失败事实并转人工（不自行降级、不把版本名改成其他版本重放）。

### 存储边界

交接协调服务**不得直连 Research Mapping SQLite 或 TerminusDB**。所有正式快照读取只经过领域服务暴露的工具；交接协调服务持有自己的 `PendingHandoff`/`HandoffDispatch` SQLite 状态库，与领域库物理隔离。

### 鉴权、审计与错误边界

- 鉴权：Bearer 令牌映射 actor，工具为只读档（`read`/`centre`）；未知令牌 HTTP 401，无授权工具返回稳定 `denied`。
- 审计：走 `sciweave-audit-trail` 接口层账本，读调用 `attempted` fail-open；记录 caller、channel、service `mapping-management`、tool、目标类型 `MappingFormalRevision` 与目标 `formal_revision_id`。
- 稳定错误分层：`invalid_arguments`（参数缺/错）→ `denied`（无权限）→ `no_such_revision` / `inconsistent` / `unavailable`（领域语义）→ `audit_unavailable`（写路径审计库不可用）。

### 验证场景（供 handoff-coordinator 实现票引用）

1. 正式事件携带 `formal_revision_id` 后，协调服务调用 `get_formal_mapping_at_revision` 得到该版本的 TaskNode/DependencyEdge 精确快照；参数（依赖边目标）重算可复现。
2. 请求一个从未成功形式化的版本号：得到 `no_such_revision`/`inconsistent`，协调服务不派发该版本，记录失败并在后续正式事件重试。
3. TerminusDB 停机：读取返回 `unavailable`，协调服务退避重试，业务上表现为该候选卡住且可观测（版本状态可见），不产生错误派发。
4. 无 `read`/`centre` 能力的调用方被稳定 `denied`；每次读取在审计账本能按 `mapping-management` + 工具名 + 目标 revision 查回。
