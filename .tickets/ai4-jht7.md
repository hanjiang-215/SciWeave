# buffer 无法对已初始化的数据库重启


## Notes

**2026-10-27T02:44:19Z**

发现（2026-10-27，实测）：对同一个 TerminusDB 数据库第二次启动 buffer，服务直接退出：

```
{status: error, code: schema_initialization_failed,
 message: TerminusDB schema initialization returned HTTP 400}
```

根因：`src/draft_buffer/store.py::initialize_schema` 只把 `200/201/409` 当成成功，但 TerminusDB v12 在类已存在时返回的是 **400**，body 为 `api:InsertDocumentErrorResponse` / `api:DocumentIdAlreadyExists`。手工复现：对同一份 schema 连发两次，第一次 200，第二次 400 `DocumentIdAlreadyExists`。所以「已经建过 schema 的库」在重启时被误判成 schema 损坏。

影响：buffer 只能对全新库启动一次；重启、换机器接管同一个库、容器重启都会起不来。这是个部署级阻塞，靠重装数据库才能绕过。

修复（提交 7b09713）：400 不再直接失败，先 GET schema 读回现有 `@id` 集合，确认 `Draft`/`NamespaceConfig`/`Operation` 都在才当作成功；缺任何一个仍然抛 `schema_initialization_failed`，不会把真坏的 schema 掩盖过去。

验证：同一个 `buffer_mcp_smoke` 库重启后 `/health` 返回 `{status:ready,protocol:mcp-streamable-http}`；buffer 套件 28 passed / 1 skipped 不变。发现过程是实机 smoke（7 个中央 MCP 逐个启动 + initialize + tools/list + 无 token 401），其余 6 个一次通过。
