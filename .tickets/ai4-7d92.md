# 落地 dead 终态与重试上限

## What to build

让失败的派发有终点。现在 `DISPATCH_DEAD` 只被 import、从未写入，`max_attempts` 只被读入配置、从不比较，失败会无限重试。

规格见 [`2026-10-26-handoff-coordinator-dispatch-defect-fix-design.md`](../docs/superpowers/specs/2026-10-26-handoff-coordinator-dispatch-defect-fix-design.md)。

## Acceptance Criteria

- [ ] 重试前比较 `attempt_count >= max_attempts`，达到则写 `dead` 并停止自动重试。
- [ ] `dead` 记录保留在 `list_dispatches` 可观察范围内，供人工经运维查询处理。
- [ ] 达到上限时不再调用发布端口，也不改动 `PendingHandoff` 状态为 `done`。
- [ ] `SCIWEAVE_COORDINATOR_MAX_ATTEMPTS` 默认值由 `3` 改为 `5`。
- [ ] 配置默认值、`README.md`、`.env.example` 三处一致。
- [ ] `attempt_count` 在每次实际重试后真实递增，不在失败瞬间就跳满。
- [ ] 新增测试：达到上限转 `dead`、未达上限仍重试、默认值为 5；第一项与第三项在修复前失败。
- [ ] 既有 9 项测试仍通过。
- [ ] 在 fer 记录验证命令、结果和提交哈希。

## Notes

- `dead` 不自动重放。指标的达成条件是「不再无限重试」，重放需要人工判断，此时代码能做的判断都已经做完了。
- 三处默认值不一致比数值本身更麻烦：运维照 README 配，行为却不同。改的时候一起改。
- 重试间隔用既有退避配置（初始 1s、指数、封顶 60s），本票不改退避策略。
