# Web 看板与平台状态可见性分支

与消息队列协作模型分支、Agent 套件接入与协作边界分支、端侧 Agent 协作与治理分支并列，确定 Web 看板对 Research Mapping、LLM-Wiki、TaskNode 进度、阻塞点和 Task Agent 外围消息监听服务状态的观察边界。首版不讨论具体前端框架、部署方案或服务自动恢复。

## Acceptance Criteria

形成可供后续产品与实现规划使用的 Web 看板领域规格：明确看板展示的对象、状态和阻塞信息；明确 Task Agent 外围消息监听服务在线状态的最小检测与展示语义；明确 Web 看板与 Codex/MCP、消息队列和领域治理写入边界；不把 Web 看板作为第二套正式写入入口。


## Notes

**2026-10-19T06:14:49Z**

Wayfinder 讨论起点（2026-10-19）：Web 看板作为与消息队列、Agent 套件、端侧 Agent 平齐的独立分支。目标是观察 Map、Wiki、TaskNode 当前进度、阻塞点，以及 Task Agent 外围消息监听服务是否在线。A2A 健康检测暂不纳入；MCP 调用失败由使用者判断服务故障或暂时抖动。首版看板不直接成为正式领域写入入口，具体读写边界后续讨论。
