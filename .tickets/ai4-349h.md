# 中央 Agent 定义层与目录结构对齐 Task Agent 模板

规格：[`docs/superpowers/specs/2026-10-28-centre-agent-definition-layer-alignment-design.md`](../docs/superpowers/specs/2026-10-28-centre-agent-definition-layer-alignment-design.md)

中央 Agent 与 Task Agent 都是 Work Agent 实例，但描述层已经长成两种东西：Task Agent 有 `agent-definitions/` + `libs/mcp-libs/` + `libs/workflow-libs/` 三处可编辑的 YAML/JSON，改口径只需改文本；中央侧的预审指令是 `runtime.py` 里一句硬编码的 `You are a SciWeave Task Agent Worker. Complete the owner's command concisely.`，既没说预审，也没说不能批准候选。

具体缺四样：

1. **没有定义层。** 五个预审角色的指令、模型、允许资源无处可写。
2. **没有「一个工作流」的载体。** 取快照 → 核事实 → 判冲突 → 写结论 → 发通知这一串只能靠 prompt 暗示。`@fast.chain` 能表达它，但没有可加载的 YAML。
3. **卡片与源码分居两处。** 五张卡片在 `toolkits/centre-agent-toolkit/mcp/`，`suite.yaml` 指 `mcp/<name>/mcp.json`；但卡片描述的是服务的能力，属于服务而不是套件。本票把卡片迁到 `centre-control/centre-agents/libs/mcp-libs/`，套件侧的 `mcp:` 段随之删除。
4. **判据版本没有落地文件。** `append_prereview_log` 必须能解析到 `<rules_dir>/<version>.json`，仓库里没有任何一份，`centre-stack` 也没配 `SCIWEAVE_*_PREREVIEW_RULES_DIR`。按现有代码，每次追加都会被拒成 `rule_set_missing`。

第 4 条不是结构问题，是这条链在真实部署里跑不通。

## 方案

按部署模板的**描述层**补齐中央侧，源码仍两侧分开（ADR-0002）：

```
centre-agents/
├── definitions/{centre-prereview.yaml, schema.yaml}
├── libs/mcp-libs/            # 五张卡片（从 mcp/ 改名迁入）
├── rules/1.0.0.json
├── gateway/{mcp,ingest,subscriber}/
└── worker/                   # 加载层与卡片翻译进这里
```

### 定义格式

沿用部署模板 schema 词汇（`version` / `agents` / `workflows`；agent 的 `identity` / `instruction` / `model` / `allowed_mcp_resources` / `resources` / `references` / `tools`），只加一种工作流类型 `Chain`：`sequence`（非空、按序）+ 可选 `cumulative`（默认 `true`）。`entry_agent` 取 `sequence[0]`，`summarizer` / `final_writer` 取 `sequence[-1]`，由加载层推导而不写进 YAML。

不套 Router / Orchestrator / Parallel：预审这一串没有分派、没有并行、没有循环。硬套 Orchestrator 会得到自由重新规划，而那会再调一次 `list_reviewable_candidates`，打破「同一时点快照」这个冲突判定的前提。

### 五个角色

| agent | MCP 资源 | 工具白名单 |
| --- | --- | --- |
| `centre-prereview-intake` | research-mapping, research-wiki | `list_reviewable_candidates` / `get_formal_mapping`；`list_reviewable_wiki_candidates` / `get_formal_wiki` |
| `centre-prereview-audit` | — | — |
| `centre-prereview-conflict` | — | — |
| `centre-prereview-verdict` | — | — |
| `centre-prereview-writer` | research-mapping, research-wiki, email-service | `append_prereview_log`×2、`send_notification` |

写权限只在一个角色身上，这是可验证的：一个「既能取快照又能写日志」的单 agent 无法在配置层证明它没有先写结论。

### 加载层

`load_centre_config()` 是唯一入口。三条硬失败、不回退：定义目录缺失/非 `1.x`、声明的资源不在卡片目录、工作流名或 `sequence` 里的 agent 未声明。

`SCIWEAVE_WORKFLOW` 选工作流，默认 `centre-prereview`；配了不存在的名字必须硬失败。

### 卡片翻译

`streamable-http` → `http`、`endpoint.url_env` → `url`、`startup.project_dir_env` → `cwd`。缺变量报错并带变量名与卡片名，不静默跳过。只发出 `allowed_mcp_resources` 声明的服务器。

### `skills` 显式传空

fast-agent 的 `skills` 默认是哨兵值（用上下文/全局技能）。不传会让无人值守的中央 Worker 去扫 home 目录——那是研究员机器的行为。所有 `@fast.agent(...)` 必须显式 `skills=[]`。

### 模型取值

定义里写具体模型名即用它；写占位符（按 `configure-` 前缀识别，部署模板已有 `configure-in-your-own-environment` 与 `configure-locally` 两个写法）回退到 `SCIWEAVE_WORKER_MODEL`；两者都没有则启动失败。出厂五段定义全写占位符：环境变量是默认，定义里的具体名字是逐 agent 的例外，两者不双写。
