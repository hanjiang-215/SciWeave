# 中央 Agent 职责收窄：情况说明

这份说明供提 issue 用。它记录的是 `feature/qiyueran` 分支上的讨论结论，不是已发布的规格。它收窄了已关闭工单 `ai4-vbnr`（中央协调 Agent 与审计体系）和 `ai4-m0vt`（首版任务执行模型）对中央 Agent 的职责描述。这两张票不由本次讨论的参与者修改，所以结论写在这里，由票的负责人裁决是否接受。

## 收窄后的职责

中央 Agent 只做一件事。

**候选版本的预审与合并。** 只针对 Research Mapping 和 LLM-Wiki 的候选版本：做格式、引用、权限、依赖、基准版本、冲突和影响范围预审，并生成必要的混合候选。不审核 Task Agent 的设计。

> 修订（2026-10-21，第二次收窄）：原第一节「部署 Task Agent」已删去。Task Agent 改由研究员端侧自持，中央不再部署、绑定或审核 agent 设计。依据工单「Task Agent 改由研究员端侧自持」。

## 取消的职责

| 原职责 | 出处 | 现在的归属 |
| --- | --- | --- |
| 初始化研究地图、创建项目、指定节点负责人 | `ai4-vbnr`、`ai4-ru15` | Project Owner |
| 调度：按正式路线和前置条件把任务分派给人员或 Agent | `ai4-vbnr`「Central Agent 可以自动完成的工作」第 2 条；`ai4-m0vt` 责任表 | 由 Project Owner 触发首次执行。上游交接就绪后由端侧订阅器自动接收 |
| 普通失败的重试、转交、请求人工接管 | `ai4-vbnr`；`ai4-m0vt` 失败分类 | 取消。可修复失败由研究员在自己的 agent 上处理 |
| 推进正式版本（PO 批准后写正式存储） | `ai4-vbnr`；`ai4-xrxw` | Project Owner 通过自己的 MCP 完成 |
| 独立的注册信息维护服务 | `ai4-e257` | 退化为按主体登记 MCP 能力的表，不是独立职责 |
| 部署 Task Agent（写入绑定与身份） | `ai4-s12u` | 取消。研究员在自己的电脑上自持 agent |

## 保留但不扩展的部分

- 不代替 TaskNode Owner 接纳执行结果。
- 不代替 Project Owner 批准正式路线、目标、依赖、激活条件、回滚或恢复。
- 不把候选、或仅被节点负责人接纳但尚未正式发布的内容送去调度。
- 不把 Mapping 和 Wiki 写进同一次提交或同一个 Proposal。
- 不替 Project Owner 在多个候选方案里做最终选择。
- 不部署、不安装、不重启、不托管研究员的 Task Agent，也不保存其模型凭据。
- 不写审计。留痕是固定工具，由 Buffer、两套管理 MCP 等写入方在写事实的同一事务里调用。

## 需要票负责人裁决的点

1. `ai4-vbnr` 把调度、重试、转交列为中央 Agent 的自动职责，本次收窄把它去掉。是否需要另立主体承担，还是接受「PO 手动触发 + 研究员自行处理失败」。
2. `ai4-m0vt` 的责任表把「创建调度、重试、转交」列为中央 Agent 的动作，同上。
3. 上游交接就绪后由谁拉起下游首次执行：已定为端侧订阅器自动接收，但订阅器本身不在中央，是否需要中央侧任何配合（如订阅登记）尚未定。

## 形态

一个 Agent，`fast-agent-mcp` 单实例常驻，能力用 MCP 工具区分。对外只通过两套互相隔离的管理 MCP 谈 Mapping 和 Wiki。

> 修订（2026-10-21）：原「复用 `task-agent` 的 Gateway 骨架、租约与审计写法」作废。端侧 Gateway 与中央 Agent 分属不同部署单元，不再共用代码。
