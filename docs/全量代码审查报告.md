## 三、低优先级（易用性 / 可维护性）

- 裸 `except Exception` 遍布（`worker/runtime.py`、`completion_publisher.py`、`dashboard_source.py`、`adapter_email.py` 等）多为有意隔离，但多数**未 `logger.exception`**，线上排障困难——建议统一补日志（与 P2-5 同类）。
- `worker/src/task_agent_worker/runtime.py`：`_execute` 用 `asyncio.run` 且异常一律吞成 `fast_agent_runtime_error`，丢失堆栈与区分度；另有死代码 `async def step()` 未使用。
- `worker/src/task_agent_worker/assembly.py:141`：`centre_root()` 用 `parents[3]` 依赖目录层级，移动源码即断。
- `email-service/config.py`：仅设 `FROM_ADDRESS` 其余为空时走“全未配置”分支，from_address 被忽略且报 not_configured，易困惑。
- `buffer/src/draft_buffer/canonical.py:9`：`canonical_json` 未 `allow_nan=False`，与 message-envelope 不一致。
- `buffer` 的 `list_drafts` 按 `submitted_at` 排序但该字段创建后不刷新（名不副实）。
- `web-ui`：多处 `new Date(value)` 无防护（非法时间致 `RangeError` 中断渲染）；`RouteView.vue` 两个 watch 存在抖动风险；`attentionItems` 用 ISO 字符串字典序比较（跨时区错）。
- `worker_runner.py` 的 `waiting` 状态无超时看门狗，长期 waiting 不可观测。
- `coordinator` 根节点每轮重写 waiting 并 commit（幂等但无谓写）。
- 测试 `coordinator/tests/test_coordinator.py:44-62`：Fake 用 `isinstance(value, Exception)`，覆盖不到真实 `SnapshotUnavailableError` 与空 documents 分支。

## 四、跨服务共性问题

1. **mapping 与 wiki 已出现“行为漂移”**：research-map 的 prereview 已修四列键（含 base + ORDER BY，ai4-sf8l），research-wiki 的同名逻辑**未同步**（P1-1）；research-map candidate 与 wiki candidate 的跨存储对账/孤儿处理也不一致（P1-4/P1-5）。建议把“正式化+预审+对账”的核心算法抽到共享包，或至少建立两侧一致性回归测试。
2. **错误吞没不记日志**是最普遍的可维护性债务（P2、低优先级多条），导致线上故障难定位。
3. **异常隔离的“宽/窄”不统一**：subscriber cli 用宽 `except Exception` 兜毒消息（好），ingest cli 只 catch `GovernanceEnvelopeError`（P0-3 崩 loop）——同族代码应统一兜底策略。
