## 3. 修复优化方案（P0 → P2）

### P0 · 已完成（本次）
- 提交 B2/B4/B5 源码修复，各为独立提交，均在 `feature/hanjiang`。
- 提交 `dsh/` 启动器与 `.env.example`，真实 `.env`/data/logs/pids 全部忽略。
- **回归证据**：`coordinator` pytest `87 passed, 2 skipped`；`subscriber` pytest `27 passed`。

### P1 · 根治与补测（建议按序）

**P1-1 B6：新增 `task_completed` 生产者（高）**
- 位置：`subscriber/src/gateway_subscriber/worker_runner.py` worker 完成分支。
- 用 `shared/message-envelope` 的 `task_completed` 模型序列化：`task_node_id / node_version_ref / formal_revision_id / mapping_domain_id`，发到 `sciweave.governance-events`。
- 验收：派发→执行→完成→`completed_fact` 落库→下游 T2 由 `blocking_dependency_missing` 转 `waiting`，全程无人工模拟。
- 单测：worker 完成时断言发布了 1 条 `task_completed`，payload 字段齐全。

**P1-2 B7：执行状态只读聚合（高，推荐方案 2）**
- 不改正式映射不可变语义；`dashboard_source._task_status` 改为按 `task_node_version_ref` 关联 gateway `execution_records` / coordinator `completed_fact` 推导状态。
- 验收：`succeeded/completed` 计数与执行事实一致，不再恒 `unknown`。

**P1-3 B9：消费组环境前缀（中）**
- `main.py` 默认组改为带环境，如 `os.environ.get("SCIWEAVE_COORDINATOR_KAFKA_GROUP_ID", f"coordinator-{env}")`；启动日志显式打印实际消费组。
- 验收：两套栈并存时事件不被负载均衡到错误一方。

**P1-4 B1 根治（中）**
- 确认 `coordinator`/`research-map`/`research-wiki` venv 均以 editable 或 wheel 安装 `shared/audit-trail`，删除「覆盖 venv 文件」的临时做法；加一条 CI 断言（import 后 `inspect` 连接参数）。

**P1-5 B10/B11/B12（低）**
- B10：`role` 枚举增加 `service`，或与 `register_workflow_agent` 的 `service:xxx` 语义统一。
- B11：`register_workflow_agent` schema 中 `principal_id` 改为必填（配合 `centre` 例外），文档同步。
- B12：wiki 启动/健康检查校验「配置域 == 数据域」，不一致时显式告警。
