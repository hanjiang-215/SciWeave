有，好兄弟，而且类似产品不少。只是它们通常分成三类：

1. **多 Agent 开发框架**：帮助开发者编排 Agent，但不是完整产品；
2. **企业级 Agent 编排平台**：提供 Agent、工具、权限、工作流和人工审批；
3. **面向特定工作的 Agent 团队产品**：例如软件开发、客服、销售或研究。

你们想做的“基于 MCP、Skills 和中央调度服务的通用科研 Agent 平台”，最接近第二类，但可以从第一类吸收底层能力，再用科研资源和科研过程追踪形成差异。

## 八、建议下一步重点验证的三个问题

### 问题一：你们是否真的需要“动态中央调度”？

有两种路线：

```text
固定工作流：
用户选择 Workflow → 中央服务按图执行
```

和：

```text
动态调度：
用户提出目标 → 中央服务动态发现 Agent、Skill 和 MCP → 生成执行图
```

建议第一版采用：

> **固定工作流为主，动态 Agent 推荐为辅。**

完全动态调度的可控性、调试和评估难度都很高。

### 问题二：你们的共享对象是什么？

如果只共享消息，产品会像聊天系统；如果共享的是结构化科研资源，才更接近科研平台。

建议优先定义：

```text
Agent
Skill
Tool
Resource
Task
Workflow
Evidence
Event
Workspace
```

### 问题三：你们和 Dify、n8n 的差异是什么？

这个问题必须在 Wayfinder 中形成明确决策。初步答案可以是：

> Dify 和 n8n 主要帮助用户构建自动化流程；你们的平台帮助科研团队管理跨 Agent 的长期研究过程，并保存资源、证据、版本和人类决策。

如果无法证明这个差异，直接基于 Dify 或 n8n 扩展可能比从零开发更合理。

## 推荐的研究顺序

1. **Dify、n8n**：了解完整产品形态；
2. **LangGraph、AutoGen、CrewAI**：了解 Agent 编排实现；
3. **Copilot Studio、Agentforce、ServiceNow**：了解企业级治理；
4. **MetaGPT、OpenHands**：了解 Agent 团队和可执行任务；
5. **SciForge、AI Scientist、RD-Agent**：了解科研特有的资源和证据需求。

最重要的比较维度不是“用了什么模型”，而是：

- Agent 如何注册；
- Agent 如何发现彼此；
- Skill 和 Tool 如何挂载；
- 中央调度如何做决策；
- 工作流是否可暂停和恢复；
- 人类如何介入；
- 资源如何共享和版本化；
- 过程是否可审计；
- 结果是否可复现；
- 多个科研组如何隔离。
