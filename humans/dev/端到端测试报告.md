## 5. 过程中发现并修复的问题

1. **venv 内 audit_trail 过期**（research-map）：运行 venv 内 `audit_trail` 为 0.2.0 旧版，缺 `check_same_thread=False`，导致 live 写审计表抛线程错误（`audit_unavailable`）。**修复**：以 `shared/audit-trail/src/audit_trail/__init__.py` 覆盖 venv 同名文件，重启 research-map MCP，写路径恢复正常。
2. **TerminusDB 边 schema 与治理校验不一致**：治理校验要求 `source/target_node_version_ref` 为 `{logical_id, version_id}` 子文档对象，而旧 seed schema 声明为 `xsd:string`，导致边文档写入 400。**修复**：以正确 schema（`NodeRef` 内联子文档）重建 `sciweave_mapping` 并重新 seed 基础路线。
3. **快照精确对账（`_contains_documents`）不匹配**：TerminusDB 会为内联子文档生成确定性 `@id`（`DependencyEdge/<vid>/<role>/NodeRef/<logical>+<version>`），若提交体未带该 `@id`，写后读回不相等 → `store_result_unknown`。**修复**：提交时按 TerminusDB 规则补齐 NodeRef 的 `@id`，对账通过。
4. **check.sh 清单复检被跳过**：Git Bash 无 `python3`，check.sh 跳过 suitecheck。**修复**：提供 `python3` shim，复检正常执行且通过。

### 遗留观察（非套件接入问题，建议上游修复）
- **coordinator MCP 的 sqlite 连接缺线程安全**：`coordinator/src/main.py` 用 `sqlite3.connect(config.sqlite_path)`（无 `check_same_thread=False`），而 MCP 服务是 `ThreadingHTTPServer`，`dispatch_root_task` 在工作线程访问主线程创建的连接会抛 `ProgrammingError: SQLite objects created in a thread...`，被 `except Exception` 吞成 `dispatch_failed`。这与本项目 audit_trail 曾出现的缺陷同类。**另**：任务节点 `executor_refs` 为空时，即使线程问题修复，`dispatch_root_task` 也会走「人工通知」路径返回未派发（属正常语义——需先为节点登记可用 executor）。
  - 修复建议：连接加 `check_same_thread=False` 并加连接级锁（配合轮询线程/MCP 线程共享）；再为根任务节点配置可用 executor 后可派发成功。
  - 本次未擅自修改并重启 coordinator（超出「仅重启 research-map」的授权范围），仅作为发现记录。
